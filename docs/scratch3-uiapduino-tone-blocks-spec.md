# 音楽（Tone）ブロック 仕様案

[Issue #4](https://github.com/tarosay/scratch3-uiapduino/issues/4) の仕様を決めるための案。
**試作中。すべて未コミット。**試作で確かめながら、仕様はまだ変わる。
実機で鳴ることは D2 / D5 で確かめた（2026-10-25、Xcratch HID 版）。それ以外は実機未確認。
2026-10-25 の議論で決まった試作の中身は「2. ブロック」の「試作（2026-10-25 の議論で決めたもの）」にまとめた。

手本は MakeCode（micro:bit）の「音楽」ブロック。**音の仕組みは基板側に作る。**
Scratch 側は Hz・拍・ミリ秒への換算と、ブロックの見た目を受け持つ。

## 0. 前提（確認済み）

| | 状態 |
|---|---|
| 今のファームの音楽の仕組み | **無い**（スケッチに tone / music / melody は 0 件） |
| プロトコル | 今は 8（v0.3.1 として公開済み）→ **9 に上げる** |
| 焼き直し | v0.3.1 に入っている書き込みブロックで、Scratch から焼ける |
| Flash | 「4. 基板側の作り」の「測った大きさ」を参照。音を入れて **Remap3 版の残りは 1788 バイト** |
| Feature Report | 32 バイト（1 コマンドで送れるのは 31 バイト） |
| 応答 | 8 バイト。中身に使えるのは 5 バイト |

### PWM の周波数はタイマー単位

CH32V003 のタイマーは、周波数を決める分周（`PSC`）と周期（`ATRLR`）を 1 組しか持たない
（`ch32v00x.h`）。チャンネル（ピン）ごとに持つのは比較値（`CHxCVR` = duty）だけ。
**PWM で出す限り、同じタイマーのピンは同じ周波数になる。**

| タイマー | HID 版 | Remap3 版 |
|---|---|---|
| TIM1 | D0 / D5 / D6 / D12 | D0 / D5 / D6 / D12 |
| TIM2 | D2 | D3 / D9 / D15 / D16 |

### 割り込みは足さない（第 1 段）

- USB はソフトウェア実装（rv003usb）で、`EXTI7_0` の割り込みで動いている。
  その割り込みは 50µs を超える（スケッチの `NEOPIXELMIN_ATOMIC` のコメント）
- コアは割り込みの入れ子（`FUNCONF_ENABLE_HPE`）を CH32V003 では有効にしていない
- 割り込みを足すと、USB の割り込みを待たせる。USB に影響が出るかは確かめていない

**だから第 1 段は割り込みを使わない。** 音の切り替えは `loop()` の中で時刻を見て行う。

### `loop()` が止まる時間がある

| 処理 | 止まる時間 |
|---|---|
| 応答を 1 つ返す（`rsp()` の `delay(12)`） | 12ms |
| キー 1 つを打つ（`keyTap()`） | 40ms 程度（`delay(20)` × 2） |
| 距離を測る | 最大 460ms（Echo 待ち） |

この間は音の切り替えが遅れる。**`delay()` を、待つ間も音を進める `waitMs()` に置き換える**
（「4. 基板側の作り」）。距離計の Echo 待ちは置き換えられない（µs を数えているため）。

## 1. 決めたこと

1-1〜1-4 は 2026-10-25 に推奨どおり決定。

### 1-1. ピンの指定

| | ブロックごとにピンを指定する（決定） | 設定ブロックで 1 本に決める |
|---|---|---|
| ブロック | 「ピン [5 ▼] で …」が毎回付く | MakeCode と同じ短さ |
| 同時に鳴らす | タイマーが違うピンなら 2 音（第 3 段で増やせるかも） | 1 音だけ |

**決定: ブロックごとに指定する。** UIAPduino は 2 音を同時に出せる。MakeCode と同じ形にすると、
その力を使えなくなる。

### 1-2. メロディの書き方

MakeCode の 8×8 のマス目は、Scratch の拡張機能の欄（8 種類）では作れない。

**決定: 文字で書く。** MakeCode が内部で使っている書き方（例: `C5 B A G F E D C`）に合わせる。
MakeCode の JavaScript 表示から写せる。

書き方の細部は MakeCode のソースで確かめた（`pxt-microbit` の `libs/core/music.ts` の
`MelodyStringReader`、MIT ライセンス）。「2. ブロック」の「メロディの書き方」に書いた。

### 1-3. テンポの既定値

**決定: 120。** MakeCode の既定に合わせる（Scratch の「音楽」は 60）。
テンポはこの拡張機能が自分で持つ。「音楽」拡張機能のテンポは読まない。

### 1-4. 停止ボタン

**決定: 鳴っている音を全部止め、予約も消す。** 「ずっと」で鳴らした音もここで止まる。
アナログ出力とサーボは今までどおり止めない。

### 1-5. 保留にするもの

| もの | 理由 |
|---|---|
| 音量 | 作りは用意する（duty を変えるだけ）。圧電ブザーで小さくなるかを実機で見てからブロックにする |
| 用意された曲（ダダダム など） | 曲データの出どころとライセンスを確かめていない |
| ビブラート・トレモロ | 第 1 段を鳴らしてから決める |

### 1-6. 作らないもの

| MakeCode | 理由 |
|---|---|
| メロディを停止する [すべて ▼] | 「すべての音を停止する」と「ピン [ ] の音を止める」で足りる |
| 音楽 [メロディの音を出した ▼] とき | 曲を鳴らすことには要らない。必要になったら足す |
| [1 ▼] 拍（値） | 休符を拍で書けるので要らない |
| 鳴らす [くすくす笑う ▼] など | 波形とエフェクトで作る音なので、矩形波だけでは別の音になる |
| 内蔵スピーカーを [オフ] にする | UIAPduino に当たるものが無い |
| 波形の選択 | PWM は矩形波しか出せない |

## 2. ブロック

### 第 1 段

```
ピン [5 ▼] で [ド ▼(鍵盤)] を [1 ▼] 拍鳴らす [終わるまで ▼]
ピン [5 ▼] で [262] Hz を鳴らし始める
ピン [5 ▼] で [3789] Hz から [3613] Hz へ [2000] ミリ秒で鳴らす [終わるまで ▼]
ピン [5 ▼] を [1 ▼] 拍休む
ピン [5 ▼] の音を止める
すべての音を停止する
ピン [5 ▼] の音が鳴っている                ◇ 真偽
[ド ▼(鍵盤)] の周波数                       ○ 値（Hz）
テンポを [120] にする
テンポを [20] ずつ変える
テンポ                                      ○ 値
```

周波数を変えて鳴らすブロック（MakeCode の 3 つめ）は、基板側では「始めと終わりの周波数が違う音」でしかない。
普通の音（始め = 終わり）と同じ仕組みで鳴るので、第 1 段に入れる。補完はリニアだけ。

### 第 1 段に足したもの：ピアノを押すと PC で鳴る

ピアノの欄（`ArgumentType.NOTE`。「60」のような音の番号が入る欄）のキーを押すと、
その音を PC のスピーカーで 0.25 秒鳴らす。「音楽」拡張機能と同じ動き。基板では鳴らさない。

- ピアノの欄は scratch-blocks の `FieldNote`。キーが押されると GUI が `PLAY_NOTE` を出す
  （scratch-gui の `lib/blocks.js`。Xcratch の配布物 `gui.js` にも同じものがあることを確かめた）
- 合図に入っているのは「音の番号」と「ブロックの拡張機能の名前」だけ。ピンは入っていないので、
  ブザーで鳴らすとしてもどのピンか決められない。だから PC だけにした
- 音はブザーに近い矩形波。Hz はブザーへ送るのと同じ整数にして、聞こえる音を揃える
- ブロックの文字では「鍵盤」を使わず「ピアノ」と書く（漢字が難しいため。本人の指摘）

### 第 1 段に足したもの：接続の ようす

「接続の ようす」（値のブロック）は「つながっている」か「切れている」を返す。
「つながっている」は真偽のブロックでステージに表示できないため、表示できる形で足した。

### 第 2 段

```
ピン [5 ▼] でメロディ [C4 D4 E4 F4 G4 A4 B4 C5] をテンポ [120] で鳴らす [終わるまで ▼]
```

メロディのブロックの文字の欄には、「メロディ」のリストのブロックをはめて使える。
Scratch はリストの中身をスペースでつないだ文字にして渡す。

### メロディの書き方（MakeCode と同じ）

`pxt-microbit` の `MelodyStringReader` の読み方に合わせる。

| 書き方 | 意味 |
|---|---|
| `C` `D` `E` `F` `G` `A` `B` | 音名。小文字でもよい |
| 後ろの数字 | オクターブ。書かなければ 4。真ん中のドが `C4`（Scratch の 60） |
| `#` | 半音上げる（`F#4`） |
| 音名の後ろの `b` | 半音下げる（`Bb4`）。先頭の `b` は音名の B |
| `-` `R` `r` | 休符 |
| `:数字` | 長さ。**単位は 4 分の 1 拍**（`:4` で 1 拍、`:2` で半拍）。書かなければ 1 拍 |
| スペース | 区切り |

- オクターブは音ごとに 4 に戻る。長さは書いた後の音にも効き続ける（MakeCode と同じ）
- 読めない音は休符として扱う（MakeCode と同じ）

決まりの一覧（`_parseMelody()` で node を使って確かめた）:

| # | 決まり | 例 |
|---|---|---|
| 1 | 音はスペースで区切る。区切らずに続けても、別々の音として読む | `C4 D4 E4`、`CDE` |
| 2 | 音の名前は C D E F G A B。小文字でもよい | `c4` |
| 3 | 音の名前の後ろの数字はオクターブ。書かなければ 4。`C4` が真ん中のド | `C5`、`C` |
| 4 | オクターブは音ごとに 4 に戻る。前の音の数字は引き継がない | `C5 D` の D は D4 |
| 5 | `#` で半音上げる | `F#4` |
| 6 | 音の名前の後ろの小文字 `b` で半音下げる。音の名前より前の `b` は音の名前の B | `Bb4`、`b4` |
| 7 | 休符は `-`、`R`、`r` のどれか | `C4 - E4` |
| 8 | 長さは `:数字`。単位は 4 分の 1 拍。何も書かなければ 1 拍 | `:4` は 1 拍、`:2` は半拍、`:8` は 2 拍 |
| 9 | 長さは引き継ぐ。一度書くと、次の `:数字` までは後ろの音と休符も同じ長さ | `C4:2 D4 E4` は 3 つとも半拍 |
| 10 | 1 拍の長さはテンポで決まる（60000 ÷ テンポ ミリ秒） | テンポ 120 なら 1 拍 500 ミリ秒 |
| 11 | 読めない文字は無視する。音の名前が 1 つも無い区切りは休符になる | `x` は 1 拍の休符 |
| 12 | 音の名前より前の数字は無視する | `3C` は C4 |
| 13 | 音は 0〜130 の番号の範囲に丸める。1 つの音の長さは最長 65535 ミリ秒 | |

例（チューリップ。そのまま写して鳴らせる）:

```
C4 D4 E4 - C4 D4 E4 - G4 E4 D4 C4 D4 E4 D4 -
```

### 試作（2026-10-25 の議論で決めたもの）

ブロックを自動で足す形はやめた。拡張機能からブロックを足すと編集画面が描き直され
（`BLOCKS_NEED_UPDATE` → `clearWorkspaceAndLoadFromXml`）、開いているピアノが閉じるため。

#### ピアノで弾いた音の記録

| # | 仕様 |
|---|---|
| 2-1 | 記録のブロックは「ピアノ (60) で弾いた音」（値のブロック）1 つだけ。返す値は、記録した音の並び（「メロディ」のリストの中身をスペースでつないだ文字） |
| 2-2 | 欄なしの「ピアノで弾いた音」は作らない |
| 2-3 | 記録するのは、2-1 のブロックのピアノで押した音だけ。ほかのブロックのピアノで押した音は、PC で鳴るだけ。どのブロックのピアノかは、選択中のブロックの印（`blocklySelected`）とブロックの文字で見分ける（試作で確かめる） |
| 2-4 | 記録先は「メロディ」という名前のリスト。1 音を 1 行に書く（例: `C4`） |
| 2-5 | 「メロディ」のリストが無ければ、拡張機能がステージに作る（すべてのスプライト用）。作る時機は、拡張機能を追加したとき、作品を開いたとき、記録しようとしたとき。音を使わない作品にも出てくる |
| 2-6 | 記録する音は全部 1 拍（長さは書かない）。オクターブは必ず書く。オクターブを変えたときは、鳴らさず記録もしない（直前に触れた部品が `data-pitch` を持つキーかで見分ける。初めは「記録される」としていたが、実機で試して本人がバグと判断した） |
| 2-7 | 休符は、ステージのリストの表示で行を割り込ませて（Enter で下、Shift+Enter で上）、`-` と書いて入れる（scratch-gui の `list-monitor.jsx` で確かめた。操作は未確認） |
| 2-8 | 記録の消し方は 2 つ。「ピアノで弾いた音を消す」（「メロディ」のリストを空にする）と、Scratch のリストの「すべて削除」 |
| 2-9 | 鳴らすときは、メロディのブロックの文字の欄に「メロディ」のリストのブロックをはめる |
| 2-10 | 記録の上限は Scratch のリストの上限（200000 個。scratch-vm の `LIST_ITEM_LIMIT`）だけ |
| 2-11 | ノート番号 0〜11（オクターブ -1）は記録しない。`C-1` の `-` が休符として読まれてしまうため |
| 2-12 | ピアノで弾いたときと、文字のメロディをリストに入れたときに、「メロディ」のリストがステージに表示されていなければ表示する（Scratch の「リストを表示する」と同じく、モニターのブロックにチェックボックスの合図を送る）。消すときと、リストを作るだけの時機には表示しない。v0.4.1 で追加（本人の指摘：表示されないと音も編集もできない） |

- ⚠ リストを作ったときは編集画面を描き直させる（`BLOCKS_NEED_UPDATE`）。描き直さないと、
  変数のブロック一覧に出ない。記録しようとしたときに作った場合は、その 1 回だけピアノが閉じる

#### 文字列を「メロディ」のリストに入れる

Scratch には、文字列を区切ってリストにするブロックが無い（Xcratch の `data_*` / `operator_*` を全部確かめた）。
Scratch のリストのブロックに倣って、入れ方ごとに 3 つ作る。文字はスペースで区切って 1 音 1 行にする。

```
[C4 D4 E4] でメロディを入れ替える
[C4 D4 E4] をメロディの後ろに足す
[-] をメロディの [1] 番目に入れる          … 1 より前は 1 番目、最後より後ろは後ろに足す
```

#### 音量（作って試す）

```
[5・A1・A2・A3 ▼] の音量を [255] にする
```

- 音量はタイマーごとに 1 つなので、メニューにはタイマーごとのピンの組を並べる。
  表記はピンのメニューと揃える。HID 版は「5・A1・A2・A3」「2」、Remap3 版は「5・A1・A2・A3」「3・9・TX・RX」
- 0〜255。255 が一番大きい音（duty 50%）。鳴っている音にもすぐ効く
- 停止ボタンで 255 に戻す。「すべての音を停止する」ブロックでは戻さない

#### エフェクト（作って試す）

```
ピン [5 ▼] で [3789] Hz から [3613] Hz へ [2000] ミリ秒 [ビブラート ▼] で鳴らす [終わるまで ▼]
```

- 今の「周波数を変えて鳴らす」ブロックとは別のブロック
- エフェクトは、なし・ビブラート・トレモロ・ウォーブルの 4 つ。揺れの周期と深さは仮の値で、
  実機で鳴らしてから直す（スケッチの `TONE_VIBRATO_*` など）
- ウォーブルは、ビブラートを速く深くしたもの（不規則には揺らさない）

#### 排他

- 「鳴らす」関連のブロック（鳴らす・休む・音量）と、「サーボ [ ] を [ ] 度にする」「ピン [ ] の出力を [ ] にする」は排他にする。
  「サーボの設定」にタイマーの区別が無く、使う人はタイマーを選べないため
- 後から使った方を動かし、先の方を止める。
  「鳴らす」関連を使ったら、サーボと出力を全部止める（出力 0）。サーボか出力を使ったら、音を全部止め、予約も消す
- 基板側で行う。アナログ出力・サーボで PWM を出しているピンを覚えておき（`pwmOutPins`）、`TONE_PLAY` と `TONE_VOLUME` の前に出力を 0 にする

#### 作らない・試さない

- 用意された曲（ダダダムなど）は作らない
- 同じタイマーで違う音を出すこと（第 3 段）は試さない

### 第 3 段（試さない）

同じタイマーで違う音を出す（トグル方式）。2026-10-25 に試さないと決めた。「4. 基板側の作り」の最後を参照。

### 鳴らし方の 3 つ

| | 意味 | ブロック |
|---|---|---|
| 終わるまで | そのピンの予約の**後ろに足す**。鳴り終わるまで次へ進まない | 待つ |
| バックグラウンドで一度だけ | そのピンの予約を**消して、これに替える**。1 回鳴らす | 待たない |
| バックグラウンドでずっと | そのピンの予約を消して、これに替える。**繰り返す** | 待たない |

「終わるまで」を続けて並べると、音は隙間なくつながる（「5. Scratch 側の作り」の先読み）。
バックグラウンドで鳴らしている BGM を止めたいときは「ピン [ ] の音を止める」。

### 引数

| 引数 | 型 | 既定 | 範囲 |
|---|---|---|---|
| ピン | メニュー（`SERVO_PIN` を共用） | 版の `PWM_DEFAULT_PIN` | PWM を出せるピン。それ以外は基板が `RSP_ERR` |
| 音 | `ArgumentType.NOTE` | 60（真ん中のド） | 0〜130 に丸める（「音楽」拡張機能と同じ） |
| 拍 | メニュー（`acceptReporters`） | 1 | 1, 1/2, 1/4, 1/8, 1/16, 2, 4。数を入れれば 0〜100 に丸める |
| Hz | 数値 | 262 | 1〜65535。0 以下なら止める |
| ミリ秒 | 数値 | 2000 | 0〜65535 |
| テンポ | 数値 | 120 | 20〜500 に丸める（「音楽」拡張機能と同じ） |

拍のメニューを MakeCode に合わせて分数にするので、メニューの値は文字列（`'1/2'`）になる。
Scratch 側で分数を数に直す。

## 3. ワイヤフォーマット

コマンド ID は `0x70`〜`0x73`。

**⚠ `CMD_MOUSE_MOVE`（`0x40`）より前で分岐させる。** `loop()` は `0x40` 以上をマウスに渡すので、
後ろに置くと吸い込まれる（NeoPixel と同じ）。

### 音の単位（エントリ）: 7 バイト

```
[開始 Hz 下位][開始 Hz 上位][終了 Hz 下位][終了 Hz 上位][長さ ms 下位][長さ ms 上位][エフェクト]
```

- エフェクト: 0 = なし、1 = ビブラート、2 = トレモロ、3 = ウォーブル

- 普通の音: 開始 = 終了
- 休符: 開始 = 0
- 周波数を変える音: 開始 ≠ 終了。長さの間にリニアに変える

### `TONE_PLAY` (`0x70`) — 鳴らす・予約する

```
[0x70][pin][mode][n][エントリ × n]       n は 1〜4（7 × 4 = 28 バイト。[4..31]）
```

| mode | 意味 |
|---|---|
| 0 | 予約の後ろに足す（終わるまで） |
| 1 | 予約を消して替える。1 回（一度だけ） |
| 2 | 予約を消して替える。繰り返す（ずっと） |
| 0x80 を足す | 直前の `TONE_PLAY` の続き。予約を消さずに足す（4 つより長いメロディを分けて送るため） |

応答（5 バイト）: `[受け付けた数][予約が鳴り終わるまでの ms（3 バイト）][予約の空き]`

予約がいっぱいなら、入る分だけ受け付ける。Scratch は残りを、空きができてから送り直す。

### `TONE_STOP` (`0x71`) — 止める

```
[0x71][pin][音量を戻すか]      pin = 0xFF なら全部
```

全部のときだけ、3 バイト目が 0 でなければ音量も 255 に戻す。停止ボタンは 1、「すべての音を停止する」は 0。

PWM を出せないピンは `RSP_ERR`。PWM のピンで鳴っていなければ何もせず `RSP_OK`。

音を止め、予約を消す。タイマーを PWMmin の設定（`ATRLR` = 255）に戻す。

### `TONE_STATUS` (`0x72`) — 鳴っているか

応答: `[TIM1 で鳴らしているピン][TIM2 で鳴らしているピン]`。鳴っていなければ `0xFF`。

### `TONE_VOLUME` (`0x73`) — 音量

```
[0x73][pin][音量 0〜255]
```

ピンのタイマーの声の音量を変える。同じタイマーのほかのピンにも効く。鳴っている音にもすぐ効く
（休符の間は無音のまま）。既定は 255（duty 50%）。

## 4. 基板側の作り

### 声（ボイス）はタイマーに 1 つ

- TIM1 と TIM2 に 1 つずつ、合わせて **2 声**
- 声はどのピンで鳴らしているかを覚える
- **同じタイマーの別のピンで鳴らすと、前のピンの音は止まり、予約も消える。**
  同じ周波数で 2 本のピンが鳴る、という分かりにくい状態を作らない

### 予約（キュー）

- 声ごとに **16 エントリ**（予約だけで 6 × 16 × 2 = 192 バイト。声の状態を含めて RAM は 240 バイト増えた）
- 「ずっと」は、予約を消費せずに先頭へ戻る。だから**繰り返せるのは 16 音まで**
- 予約がいっぱいのときは、鳴らし終わった分を詰めてから足す（「ずっと」のときは詰めない）

### 周波数の出し方：`ATRLR` も使う

PWMmin は `ATRLR` を 255 に固定し、`PSC` だけで周波数を決める。出せるのは `187500 ÷ 整数` で、
高い音ほどずれる（ド8 で +31 セント）。

**音を鳴らしている間は、`ATRLR` も変える。** `PSC` を、`ATRLR` が 16 ビットに収まる一番小さい値にし、
`ATRLR` で細かく合わせる。`48MHz ÷ ((PSC+1) × (ATRLR+1))` になる。
duty は `CHxCVR = (ATRLR+1) × 音量 ÷ 512`（音量 255 で 50%）。

計算上のずれ（Hz を整数に丸めた分を含む。実測ではない）:

| 音 | 狙い | PWMmin のまま | `ATRLR` も使う |
|---|---|---|---|
| ド4 | 261.63 Hz | +4 セント | +2.5 セント（整数への丸め） |
| ラ4 | 440 Hz | +1 セント | ほぼ 0 |
| ド7 | 2093 Hz | +11 セント | ほぼ 0 |
| ド8 | 4186 Hz | +31 セント | ほぼ 0 |

ド4 より下は、Hz を整数に丸める分のずれが残る（ド2 で −11 セント）。圧電ブザーは低い音がほとんど鳴らないので、
送る単位は整数の Hz のままにする。

止めたら `PSC` と `ATRLR` を PWMmin の値に戻す。そのタイマーの他のピンでアナログ出力を使うため。

`ATRLR` と比較値はプリロードを有効にして書く（`TIM_ARPE` と `OCxPE`）。周期の途中で `ATRLR` を
今のカウンタより小さくすると、カウンタが 65535 まで回って音が途切れるため。周波数を変える音は 1ms ごとに
書き換えるので、これが毎回起きてしまう。音の始めだけは `TIM_UG` で今すぐ切り替える。
待つと、低い音の後では前の音の 1 周期ぶん（8Hz なら 125ms）次の音が遅れる。

### 時間の測り方

- `millis()` は使わない（Flash を 2.2KB 食う。スケッチの既存の方針）
- `SysTick->CNT`（48MHz で数える 32 ビット）の差で測る。距離計と同じやり方
- 1 音は最長 65.5 秒、`SysTick` が 1 周するのは約 89 秒なので、音ごとの差なら折り返しても正しい

### `toneService()` と `waitMs()`

- `toneService()`: 声ごとに「今の音が終わったか」を見て次の音へ進める。周波数を変える音なら、
  経過時間に合わせて周波数を計算し直す（1ms ごと程度）
- `loop()` の空き時間に毎回呼ぶ
- スケッチの `delay(n)` を `waitMs(n)` に置き換える。`waitMs()` は待つ間 `toneService()` を呼び続ける。
  応答（`rsp()` の 12ms）やキー入力の待ちの間も、音が遅れずに進む

### ピンを別の用途に使うと止まる

ピンを使うコマンド（ピンの設定・デジタル出力・アナログ出力・サーボ・距離計）がそのピンに来たら、
先にそこで鳴っている音を止め、予約を消す。読むだけ（デジタル入力）なら止めない。
Remap3 版でシリアルを始めたときも、D15 / D16 で鳴っていれば止める。
止めないと、声はピンを失ったまま「鳴っている」と答え続ける。

### 周波数の計算に割り算を使う

`PSC` と `ATRLR` を決めるのに 32 ビットの割り算が要る。CH32V003 には割り算の命令が無いので
ソフトウェアになるが、PWMmin の `Pwm_freq_TIM*` がすでに使っているので Flash は増えない。

周波数を変える音は、1ms ごとにこの計算をする。1 回あたりの時間はまだ測っていない。
進み具合は 1024 分率で計算する（ms のまま掛けると 32 ビットを超える。64 ビットの演算は Flash を食うので使わない）。

### 関数は声の番号を取る

Arduino は関数の宣言を自動で作ってスケッチの先頭近くに置く。引数に構造体（`ToneVoice`）を書くと、
構造体の定義より前でその名前が使われてビルドが通らない。だから声を受け取る関数は番号（0 / 1）を取る。

### 測った大きさ（2026-10-25、コア 1.2.15）

| | 音を入れる前 | 入れた後 | 増えた分 | 残り |
|---|---|---|---|---|
| HID 版 `.bin` | 12232 | 13988 | +1756 | 2396 |
| Remap3 版 `.bin` | 12804 | 14596 | +1792 | 1788 |
| RAM（グローバル変数） | 744 | 984 | +240 | 1064 |

試作（エフェクト・音量・排他を足した後）: HID 版 14608、Remap3 版 15212（残り 1172）、RAM 1056。

増えた分のうち `Pwm_write`（510 バイト）は、呼ぶ場所が 2 か所になって `main` から外に出ただけ。
音の仕組みそのものは `toneService` 244、`voiceStop` 194、`voiceOut` 130、`voiceBegin` 108 などと、
`main` に埋め込まれた `doTone`。

### 第 3 段（試作）：同じタイマーで違う音

タイマーの「トグル」モード（`TIM_OCMode_Toggle`）で、比較値に達するたびにピンを反転させる。
割り込みで次の比較値を「前の比較値 + 半周期」へ進めれば、チャンネルごとに違う周波数が出る。

確かめること:

- USB の割り込み（50µs 超）に待たされても、半周期より短ければ音は崩れない。ド8 の半周期は約 119µs
- こちらの割り込みが USB を待たせて、通信が落ちないか

**どちらも試作で確かめるまで分からない。** 第 1 段とは別に進める。

## 5. Scratch 側の作り

### 換算

- ノート番号 → Hz: `440 × 2^((n − 69) ÷ 12)` を整数に丸める
- 拍 → ms: `拍 × 60000 ÷ テンポ`

### 「終わるまで」と先読み

1. `TONE_PLAY`（mode 0）を送る。応答に「予約が鳴り終わるまでの ms」が入っている
2. **その ms から 30ms 引いた時間**だけ待って、ブロックを終える
3. 次の「〇拍鳴らす」は、前の音が終わる前に予約に入る。基板が隙間なくつなぐ

30ms は USB の往復 2 回分。ブロックは音より 30ms ほど早く終わるが、聞き分けられる差ではない。
曲のテンポは基板の時計だけで決まるので、USB の揺れで遅れたり詰まったりしない。

### メロディ（第 2 段）

文字を Scratch 側でエントリに直し、4 つずつ `TONE_PLAY` で送る（2 回目からは mode に 0x80）。
予約に入りきらない分は、応答の「空き」を見て送り直す。

### 停止ボタン

`_releaseInput()` の後ろで `TONE_STOP`（`0xFF`）を送る。実行待ちを捨てた後に送るので、捨てられない。
ウィンドウを閉じるとき（`beforeunload`）も同じ経路で送るが、間に合う保証は無い。

## 6. 制約（README に書く）

- **同時に鳴らせるのは 2 音まで。** タイマーの違うピン（TIM1 と TIM2）を使う
- **音を鳴らしているタイマーでは、アナログ出力とサーボの周波数が狂う。** 音を止めれば戻る
- アクティブ型（電圧をかけるだけで鳴る）のブザーでは、音の高さは変わらない
- 距離を測っている間（最大 460ms）は、音の切り替えが遅れる
- **「ずっと」で鳴らしたまま Scratch を閉じると、鳴り続けることがある。** 基板を抜けば止まる。
  基板の見張り（最後のコマンドから 5 秒）はキーとマウスを離すだけで、音は止めない。
  Scratch が何もしていない間も BGM を鳴らし続けたい場合があるので、見張りで止めることはしない

- 周波数を変える音が滑らかに聞こえるか
- 音量（duty）を下げて、圧電ブザーの音が小さくなるか
